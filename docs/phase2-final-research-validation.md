# Phase 2 final research traceability — exact ID membership and case specifications

## Provenance and boundaries
- The source matrix `research/phase2_exact_mapping.csv` was manually curated from OWASP ASVS **5.0.0** (the official `v5.0.0` CSV), OWASP WSTG **4.2** references in the original Phase 2 matrix, and MITRE CWE **5.0** canonical weakness references. IDs are **not** generated by an AI rule engine.
- The two source datasets were imported and SHA-256-receipted on the user's Kali machine, **not provided to this project update**. This archive therefore does **not** contain or claim to have inspected those locally imported bytes.
- `tools/validate_research_mapping.py` checks exact ID membership against the local downloaded datasets. It emits `research/phase2_mapping_membership_receipt.json` on Kali. It does not assert that every requirement is fully tested by the scanner.
- **No actual positive/negative vulnerability examples are included.** `research/fixtures/case_specifications.json` describes pre-registration of expectations for future authorized lab testing; none are observations, vulnerability labels, or measurement results.

## Kali reproducibility (keep your local source downloads)
Copy or preserve the two downloaded files into `research/datasets/external/` of this updated project:
- `OWASP_Application_Security_Verification_Standard_5.0.0_en.csv`
- `cwe-5.0-cwec_latest.xml.zip`

Alternatively, provide paths using `--asvs` and `--cwe`.

```bash
python tools/validate_research_mapping.py \
  --asvs ~/Downloads/owa-phase2/research/datasets/external/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv \
  --cwe ~/Downloads/owa-phase2/research/datasets/external/cwe-5.0-cwec_latest.xml.zip

```

**Expected:** all referenced identifiers exist in the imported ASVS 5.0.0 and CWE 5.0 datasets. If they do not, the command exits unsuccessfully and records the offending IDs. Avoid claiming full Phase 2 validation until this passes and semantics/fixtures are independently reviewed.

## Cautions in exact mapping
- `CHK01`: ASVS V4.1.2 explicitly distinguishes browser-based redirects from API/service endpoints; a blanket redirect policy is not always required.
- `CHK02`: a CSP `frame-ancestors` directive's presence is not equivalent to an effective block.
- `CHK03`: header absence/presence does not establish correct browser MIME processing; no CWE assigned.
- `CHK04`: cookie policy depends on session sensitivity and intended cross-site behavior.
- `CHK05`/`CHK06`: no defensible direct ASVS requirement ID identified; keep blanks.
- `CHK07`: reflection alone is **not** cross-site scripting; do not assign XSS CWE based on reflection.
- `CHK08`: a 500 response does not establish an exploitable input-validation weakness; CWE left blank.
- `CHK09`/`CHK10`: authorization requires confirmed order ownership and authorization policy in the AuditShop fixture.
- `CHK11`: a boolean differential is an *indicator*; not by itself confirmed SQL injection.
- `CHK12`: checks old session artifact after logout, not all other devices, refresh tokens or federated sessions.
