# Phase 7 — Independent benchmark provenance and evaluation

## Meaning of *independent*

OWASP BenchmarkJava v1.2 is an external source of truth, published by the
OWASP Benchmark project rather than generated by our scanner or AI. The 15
verbatim records bundled here are a **small source excerpt**, not a complete
copy of the original 2,740-case dataset. The subset is a provenance/label
pipeline test, not an independently executed detection benchmark.

- Upstream: https://github.com/OWASP-Benchmark/BenchmarkJava/blob/master/expectedresults-1.2.csv
- Public documentation: https://owasp.github.io/www-project-benchmark/
- Included categories: SQL injection, CWE-89; Secure Cookie Flag, CWE-614.
- `research/phase7/external/owasp_benchmark_java_1_2_verified_subset.csv`:
  15 source-authored rows, preserving IDs, labels, categories and CWEs.
- `research/phase7/human_label_review.csv`: explicit **PENDING** review items.
  Nothing in this file should be treated as an approved review unless a
  qualified human verifies the original case behavior, scope and applicability.
- `research/phase7/external_manifest.json`: dataset and mapping SHA-256, one
  mapping entry per CHK01–CHK13, and validation caveats.
- `research/phase7/external_score.json`: the deliberately UNEXECUTED result.

## Commands

```bash
python tools/phase7_evaluation.py prepare

python -m pytest -q tests/test_phase7_evaluation.py
python -m pytest -q
```

The original upstream CSV is not bundled whole. To assess more than the
included excerpt, obtain the entire upstream file from the project, record
its SHA-256 and immutable commit, and review the new case mappings manually.
The import tool in this release intentionally accepts only the two
reviewed category/CWE pairs, not arbitrary CSV columns or synthesized labels.

## Scoring conventions

- **UNEXECUTED**: no valid executed observation; **never** silently FN.
- **ABSTAINED**: `Potential`, `Not Tested`, or `Inconclusive`; does not count as
  a true-positive vulnerability claim.
- **TP**: confirmed finding on an independently labeled vulnerable case.
- **FP**: confirmed finding on a labeled non-vulnerable case.
- **TN**: no issue observed on a labeled non-vulnerable case.
- **FN**: no issue observed on a labeled vulnerable case, *only after* a valid,
  executed and appropriately mapped observation exists.
- Precision, recall, FPR: **null** (undefined) if their denominators are 0.
- Coverage includes 13 CHK identifiers, with explicit `case_count=0` where
  there are no cases selected.

## Prerequisites for actual independent benchmark execution

1. Obtain and pin the complete benchmark app/labels. Verify its integrity.
2. Run that application **only on a loopback-isolated test machine**.
3. Independently review the correct endpoint, parameter, CWE, permission
   and application configuration for each case. Document names of reviewers,
   review ticket, source version and exact expected labels.
4. Validate scanner applicability and adapt any incompatible interface in a
   separate, documented implementation. Existing CHK11 is AuditShop-specific:
   it is *not* an arbitrary BenchmarkJava servlet SQLi detector. CHK04's cookie
   attribute observations do not imply per-servlet CWE-614 classification.
5. Run full CLI and preserve deterministic evidence artifacts. Do not use AI
   to generate expected labels, verdicts or observations.
6. Score only with matched benchmark case IDs, explicit CHK IDs, approved
   endpoint identities, preserved evidence files and verified SHA-256.
7. Manually check source/verdict equivalence. A matching CWE ID alone is
   insufficient to claim benchmark support.

### Observation file (for future human-validated execution)

`--observations /path/observations.json --artifacts-root /path/evidence-dir`

```json
{
  "schema_version": 1,
  "observations": [
    {
      "case_id": "BenchmarkTest00008",
      "check_id": "CHK11",
      "status": "Potential",
      "benchmark_endpoint": "localhost/<manually-approved-endpoint>",
      "human_review_reference": "<review-ticket>",
      "evidence_path": "<relative-path-to-existing-evidence.json>",
      "evidence_sha256": "<actual-sha256-of-evidence-bytes>"
    }
  ]
}
```

The evaluator verifies the evidence file's bytes, confines paths under the
provided artifacts directory, and enforces check/case mapping; it does not
independently attest that a text `human_review_reference` is genuine. That
claim still requires human signoff and reproducible benchmark controls.

## Scope limitations

- **No independent benchmark execution** occurred in this environment.
- The environment has no network access to download/build an external lab
  and no pinned, installed benchmark server; constructing a substitute app
  would not be independently labeled.
- WebGoat and Juice Shop are valuable *independent projects* for follow-up
  but do not provide a drop-in CHK01–CHK13 per-request label oracle. Their
  documentation must be reviewed for applicable scenarios.
- Existing first-party Phase 4/5 fixture results remain useful regression
  evidence but **must not** be pooled into independent benchmark metrics.
- Source excerpt was retrieved from the upstream master URL; immutable
  source commit ID and full-file SHA-256 need to be pinned before publication.
