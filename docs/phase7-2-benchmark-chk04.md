# Phase 7.2 — External OWASP Benchmark Java 1.2 CHK04 evaluation

## Scope and scientific claim

This is an **adapter calling the unchanged production `auditor.checks.cookies.review_cookies`**, not the full CLI's CHK04 scan or an independent scanner end-to-end benchmark. No AI is used. Ground truth comes from `expectedresults-1.2.csv` in the pinned Benchmark Java container, not generated by this project.

Two source-authored cases are included:

| Case | Endpoint | Evaluated request | Source label | Anticipated CHK04 status |
|---|---|---|---|---|
| BenchmarkTest00016 | `/benchmark/securecookie-00/BenchmarkTest00016` | GET with `BenchmarkTest00016` header | non-vulnerable, CWE-614 | `No Issue Observed` |
| BenchmarkTest00087 | `/benchmark/securecookie-00/BenchmarkTest00087` | GET seed cookie, then POST with that cookie | vulnerable, CWE-614 | `Potential` (abstains) |

The GET setup response for 00087 contains a Secure cookie and **must not** be mistaken for the vulnerable POST response. `review_cookies()` reports missing Secure as **Potential**, which scores as **ABSTAINED**, **not TP**. A clean 00016 may score TN only after independent human review.

This adapter deliberately leaves the other 13 imported Phase 7 cases **UNEXECUTED**; it does not modify `research/phase7/external_score.json` or the original Phase 7 scoring contract.

## Evidence contract and privacy

Each live observation records the exact method, endpoint, status, raw HTTP response headers, body length and body SHA-256 (not response body or request cookie). CHK04 itself retains no cookie values, while the separate `*.http-evidence.json` files **do contain raw Set-Cookie values** so the original detector can be replayed. These files are created with owner-only mode `0600`; do not publicly publish them without separate redaction. The public manifest contains only detector observations without raw values, per-file SHA-256, runtime/source attestation and CHK04 source hash.

The offline verifier recomputes file hashes and re-runs unchanged CHK04 against saved response headers. It refuses altered methods, URLs, detector code, pinned source label file or evidence bytes. It does **not** cryptographically prove that an attacker with write access to all files could not replace the entire evidence bundle. Preserve a separate signed/immutable SHA-256 ledger for stronger chain-of-custody claims.

## Interpretation and limits

- No external benchmark HTTP requests were executed by the development environment used to build this ZIP. Actual Kali execution is required.
- 00016 non-vulnerable + `No Issue Observed` ⇒ TN **only after human review**.
- 00087 vulnerable + `Potential` ⇒ ABSTAINED **only after human review**, not TP.
- Without reviewer approval both captured cases remain PENDING_REVIEW (not scored), and the remaining 13 are UNEXECUTED.
- If denominators are zero, precision/recall/FPR are `null`, not zero or 100%.
- This is two selected, nonrandom tests, not an independently representative detection-accuracy study. The 00087 cookie might be a deliberately insecure example without proving a practical session compromise.
- CHK11 remains AuditShop-specific and is not exercised here.
