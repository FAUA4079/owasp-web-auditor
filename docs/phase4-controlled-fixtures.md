# Phase 4: Ground-truth indicator testing in isolated controlled fixtures

This phase executes the previously specified 24 cases (2 each for CHK01–CHK12) against the existing Python detection code. No AI is involved. The harness uses `httpx.MockTransport`, not remote websites, and the existing AuditShop test scenario simulator. The associated **expected labels represent observable indicators under laboratory assumptions**; they are not proof of exploitable vulnerabilities.

## Reproduce

```bash
python -m pip install -e . pytest
python tools/phase4_benchmark.py
python -m pytest -q
```

Output is saved to `research/phase4/benchmark_results.json` and `research/phase4/benchmark_report.md`. The runner verifies that sensitive fixture strings are not retained. Authenticated assessments use temporary directories and pre-existing AuditShop test identities, with AI disabled. Dataset IDs and source provenance remain in the existing Phase 2 files. Benchmark cases are **not part of the official ASVS or CWE datasets**, and are labeled as custom local fixtures.

The case IDs and expected labels derive from `research/fixtures/case_specifications.json`; the observations are generated by actual function execution and stored in the results file. The JSON also records the SHA-256 of the case-specifications file.

## Metrics and limitations

`Potential` and `Confirmed` are counted as positive *indicators*. `No Issue Observed` is negative. `Inconclusive` or `Not Tested` are abstentions and are **excluded from precision/recall denominators**, which must always be reported alongside abstention rate. Because the fixtures are engineered to cover documented branches, resulting precision and recall **must not** be described as performance on representative real-world websites or independent benchmarking.

* CHK01: Redirect simulation does not validate live TLS or transport encryption.
* CHK02: Presence of framing protection yields an `Inconclusive` response, correctly preserving uncertainty.
* CHK03–CHK06: Metadata and body recognizer tests cannot establish exploitability in browsers.
* CHK07: Reflection is not evidence of XSS.
* CHK08: A 500 response alone is not proof of injection or service availability impact.
* CHK09–CHK12: AuditShop-specific authenticated testing, not generic authorization assessment. CHK11's `Potential` result is not proof of SQL execution.

## Required follow-up before independent accuracy claims

1. Execute the same rules through the full CLI against localhost HTTP fixtures and controlled TLS endpoints (where relevant), including auth credential isolation.
2. Validate reporter evidence integrity and reproducibility across Kali Python versions.
3. Add *independent* secure and insecure test applications or published benchmarks, preserve their source versions/hashes/licenses, and apply independent labels before observing scanner results.
4. Measure ambiguous cases, class imbalance, per-rule accuracy and calibration; avoid presenting policy-dependent observations as confirmed weaknesses.
5. Run the third-party benchmark only on explicitly authorized lab targets.
